# 解冻事件 × 封批态拆轨说明（2026-11-23 当日封口）

## 问题

解冻空桩事件被当成封批态补丁：封批页显示「已封」，解冻空桩仍挂「待提交」，
温谱与封批快照各执一词。根因是同一状态字段被两条轨混写。

## 立场（已封口，折中禁用）

解冻轨与封批轨拆轨，两边不得混用。本仓取**甲路径**：

- **甲路径（采用）**：解冻事件不得写封批正式字段。`temp_batches.status/generation/sealed_at`
  零改，`seal_snapshots` 零写；批次处于正式封批或影子封批态时，解冻事件一律 **409 拒收**，
  并记审计 `解冻偏航`（payload `verdict=拒写`）。
- 乙路径（未采用）：解冻只落影子状态草稿，正式封批零改，待复核晋升，否则草稿回滚。
- 折中路径：禁用。

## 口径细则

- **正式封批** 只认 `seal_snapshots`：`status='已封批'` 且 `batch_generation` 等于批次当前代次。
- **影子封批态**：`temp_batches.status='已封批'` 但无同代正式快照。任一视图（批次/封批/温谱/
  线路/空桩/对账）一律显示为 `影子封批·待复核`，**不得显示为已封**；温谱拒导。
- **解冻轨**：空桩登记只写 `thaw_event_jobs`（`待提交`），不动封批轨。
- **互斥**：正式封批仍挂解冻待提交 = 两轨异态；有解冻待提交时封批服务拒封（`封批偏航`）。

## 并发

两人同时对同一批次提交解冻空桩须抢 `batch:{id}` 封批锁（先提交锁行再判态）。后到者只写
`contention_log` 争用痕，不写解冻态、不改批次态。

## 五视图同态

`GET /api/track/state` 及各列表接口返回的 `track.consistency_token` 由同一份轨态指纹生成；
空桩、封批、批次、温谱、线路（及对账）读同一票。票不一致即有批次两轨异态。

## 偏离

任何偏离本口径的改动记「解冻偏航」并拒写；不得只改解冻空桩提示语了事。
